# Инструкции для работы над проектом

1. Перед работой читать `memory-bank/README.md`, `activeContext.md`, `progress.md`, затем документы по текущей задаче.
2. Исходное ТЗ — PDF в корне. Обязательные требования и пожелания различаются в `docs/requirements/`. Не представлять рекомендации как требования заказчика.
3. Решения со статусом OPEN в `docs/decisions/open-decisions.md` ещё не приняты. При принятии фиксировать вариант, основание, дату и связанные изменения. Явные указания пользователя имеют приоритет.
4. По окончании содержательного этапа обновлять activeContext и progress; при изменении правил — business-rules и связанные требования/архитектуру.
5. Дословно дописывать пользовательские задания в `AI_PROMPTS.md`. Не сохранять системные сообщения, скрытые рассуждения, tool traces и секреты. Не придумывать время или сообщения.
6. В `AI_NOTES.md` отражать реальное использование AI и фактическую проверку. Не заявлять несуществующие тесты, ручные проверки или отклонённые человеком предложения.
7. Реализовывать финансовые расчёты на сервере. Не выгружать все продажи для агрегации в браузере. Проверять статусы, знаменатели, дублирование при JOIN и границы периода.
8. Сохранять простой масштаб архитектуры. Авторизация, mobile layout, admin panel и облачное развёртывание вне задания.
9. Backend и PostgreSQL реализованы, frontend пока каркас. Не объявлять полный dashboard готовым; инструкции запуска должны отражать фактическую готовность.
11. Backend — .NET 10; unit/integration/e2e — NUnit (ADR-001). Тесты БД выполнять на PostgreSQL, не подменять EF InMemory.
10. По указанию пользователя оформлять сообщения коммитов на русском языке и разбивать изменения на осмысленные этапы.
