## Запуск

Целевая команда из ТЗ:

```sh
docker compose up --build
```

**На текущем этапе эта команда не запускает приложение.** `docker-compose.yml` содержит только явно обозначенную заготовку. При реализации нужно добавить три сервиса, Dockerfile для backend и frontend, readiness БД, автоматические миграции и seed. Принятый адрес будущего dashboard — `http://localhost:8080`. В готовом решении потребуется только установленный и запущенный Docker с Compose, без ручной установки .NET, Node.js и PostgreSQL на хост.

## Бизнес-правила v1 — принято 2026-09-25

Включать в финансовую аналитику только `Paid`; `Cancelled` и `Refunded` показывать в последних продажах, но исключать из KPI. Выручка = сумма `quantity × unitPrice`; себестоимость = сумма `quantity × unitCost`; валовая прибыль = выручка − себестоимость; маржа = прибыль / выручка; средний чек = выручка / число уникальных оплаченных продаж. При нулевом знаменателе отношение отсутствует (`null`, в UI «—»).

Принят предыдущий период той же длительности в календарных днях непосредственно перед выбранным. Бизнес-зона Europe/Moscow; даты включительно, SQL-диапазон полуоткрытый. Правила возвратов, сравнения и ранжирования приняты: [D-01–D-08](docs/decisions/open-decisions.md). Полные правила и примеры — в [business-rules.md](docs/business-rules.md).

## Технические решения v1 и кандидаты индексов

Приняты модульный монолит, прямые EF Core запросы без универсального Repository, SQL-агрегации и DTO, единый origin frontend/API через proxy. Кандидаты индексов: `Sales(SoldAt, Id)` для истории, частичный индекс по дате для `Paid`, `SaleItems(SaleId)`, `SaleItems(ProductId)`, `Products(CategoryId)`, `Sales(ManagerId)`, `Sales(CustomerId)`. Итоговый набор определяется запросами и планами выполнения; индексы ещё не созданы. См. [архитектуру](docs/architecture.md).

## Seed v1

Принято: 20 менеджеров, 75 клиентов, 6 категорий, 48 товаров, 3 000 продаж за 12 месяцев. Увеличение в 10 раз отменено. Фиксированные seed/версия генератора и anchorDate обеспечивают воспроизводимость при одинаковых параметрах; по умолчанию anchorDate — бизнес-дата первого запуска.

## Timebox и незавершённая работа

ТЗ задаёт ориентир 8 часов фактической работы. Бюджет ещё не учтён; нельзя утверждать, что он исчерпан. На этом этапе не реализованы API, UI, схема БД, seed, контейнеризация и тесты. [План](docs/implementation-plan.md) распределяет будущую работу; при сдаче заменить этот раздел фактическими результатами, затраченным временем и оставшимися ограничениями.

Для дальнейшего production-развития можно рассмотреть историю возвратов и изменений статуса, мониторинг, резервное копирование и оптимизацию под реальные объёмы. Это предложения вне текущего задания. Авторизация, mobile layout, admin panel, Kubernetes, облачное развёртывание и сложная распределённая архитектура в scope ТЗ не входят.
