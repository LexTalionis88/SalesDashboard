# Реестр решений

**Все решения ниже имеют статус OPEN.** Рекомендации — проектные предложения AI для дальнейшей реализации, а не уже принятые пользователем правила. ТЗ разрешает разработчику самостоятельно выбирать многие варианты; OPEN не означает обязательного отдельного согласования с заказчиком. При выборе фиксировать дату, вариант и основание, затем синхронизировать бизнес-правила, README, архитектуру и проверки.

P0 — влияет на схему/базовые расчёты или запуск; P1 — решить до соответствующего блока; P2 — допустимо отложить до завершения обязательного объёма.

## Как фиксировать принятое решение

Для небольшого выбора достаточно заменить OPEN на ACCEPTED в строке и записать дату/основание ниже. Для значимого изменения бизнес-семантики создать отдельный `ADR-NNN-<name>.md`: контекст, выбранный вариант, альтернативы, последствия, затронутые требования/проверки. Перечень фактически принятых решений пока пуст.
