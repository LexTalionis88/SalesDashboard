# Реестр решений

**Решения по умолчанию приняты пользователем для первой версии 2026-09-25.** Основание: «С решениями по умолчанию - я согласен. Для первой версии этого будет достаточно. Зафиксируй это». D-01–D-09 и D-11–D-15 — ACCEPTED. D-10 — PARTIALLY ACCEPTED: подход и предложенные инструменты приняты, точные версии и конкретный UI-набор предстоит выбрать при создании проектов. Принятие решения не означает его реализацию. Имя файла сохранено для совместимости ссылок.

P0 — влияет на схему/базовые расчёты или запуск; P1 — решить до соответствующего блока; P2 — допустимо отложить до завершения обязательного объёма.

## Как фиксировать принятое решение

Для небольшого выбора достаточно заменить OPEN на ACCEPTED в строке и записать дату/основание ниже. Для значимого изменения бизнес-семантики создать отдельный `ADR-NNN-<name>.md`: контекст, выбранный вариант, альтернативы, последствия, затронутые требования/проверки. 2026-09-25: приняты варианты по умолчанию для v1. Запрос на увеличение seed в 10 раз отменён пользователем: сохраняются 20 менеджеров, 75 клиентов, 6 категорий, 48 товаров и 3 000 продаж за 12 месяцев. Сравнение периодов реализуется после обязательного объёма. Уточнение 2026-09-25: backend реализован на .NET 10, unit/integration/e2e — NUnit (ADR-001). Контракты описаны в api-contract.md и OpenAPI. Версии backend закреплены.

2026-09-25: frontend реализован на React, TypeScript, Vite, TanStack Query и Recharts. Конкретные версии закреплены в `frontend/package-lock.json`; UI использует собственные CSS-компоненты.
