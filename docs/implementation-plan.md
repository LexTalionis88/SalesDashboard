## Порядок и зависимости

1. Принять P0-решения; выбрать версии и зафиксировать начало/остаток timebox.
2. Создать реальные frontend/backend проекты, Dockerfile и рабочий Compose, получить сквозной запуск.
3. Создать схему, миграции, транзакционный seed; проверить повторяемость при одинаковых параметрах и идемпотентность старта.
4. Реализовать общие правила периода/статусов, KPI и рейтинг, затем остальные агрегаты и ограниченную историю. Проверять бизнес-результат по мере реализации.
5. Собрать UI с единым периодом и корректными состояниями. Подключить реальные API вместо постоянных моков.
6. Включать SHOULD (сравнение периодов, расширенные строки рейтинга) только при готовом обязательном сценарии. MAY-блоки — последними.
7. Выполнить [план проверки](verification-plan.md), оформить фактическую сдачу. При дефиците времени прекратить расширение функциональности и сохранить рабочий запуск.

## Предлагаемые этапы Git

`Создать структуру проекта и добавить исходное ТЗ` → `Настроить запуск приложения через Compose` → `Добавить модель продаж и начальные данные` → `Реализовать API аналитики` → `Создать интерфейс dashboard` → `Добавить проверки и завершить документацию`.

Локальный Git-репозиторий создан 2026-09-25, основная ветка — `main`. Подготовленные материалы фиксируются отдельными тематическими коммитами. По указанию пользователя сообщения коммитов оформляются на русском языке. Последующие этапы выше остаются планом; удалённый репозиторий и публикация не настроены.
