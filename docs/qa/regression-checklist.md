# Регрессионный чек-лист

## Запуск

- [ ] Docker Desktop запущен.
- [ ] `docker compose up --build` завершается успешно.
- [ ] Все контейнеры имеют ожидаемый статус в `docker compose ps`.
- [ ] `http://localhost:3000` открывается.
- [ ] `/api/health/ready` возвращает 200.

## Dashboard

- [ ] Видны все пять KPI.
- [ ] Сегодня, 7 дней, 30 дней, этот месяц и прошлый месяц меняют даты.
- [ ] Ручной период с from > to показывает ошибку и не вызывает API.
- [ ] График содержит выручку, прибыль и количество продаж.
- [ ] Рейтинг переключается между двумя режимами.
- [ ] Лучший менеджер не меняется из-за режима сортировки.
- [ ] Категории и top-5 товаров отображаются.
- [ ] История содержит дату, клиента, товары, менеджера, сумму, прибыль и статус.
- [ ] Пустой период показывает empty state.
- [ ] Ошибка API показывает кнопку повторной загрузки.
- [ ] Быстрая смена периода не показывает данные старого запроса.
- [ ] На desktop и mobile нет критического overflow.

## API и данные

- [ ] Paid входит в KPI, Cancelled и Refunded не входят.
- [ ] Границы from/to проверены на точных timestamps.
- [ ] limit принимает 1—100 и отклоняет остальные значения.
- [ ] Пустые результаты содержат ожидаемые null и пустые массивы.
- [ ] Повторный запуск не создаёт дубли.
- [ ] В ProblemDetails нет stack trace и SQL.

## После проверки

- [ ] Результат записан в execution report.
- [ ] Для каждого дефекта указан приоритет и воспроизводимые шаги.
- [ ] Открытые P0/P1 согласованы с владельцем продукта.
