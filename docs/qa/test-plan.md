# План тестирования

## Цель

Подтвердить корректность расчётов, периодов, статусов продаж, отображения
dashboard, API-контракта, seed, контейнерного запуска и диагностируемости.

## Объект тестирования

- API `/api/dashboard`, `/api/sales`, `/api/health/ready`;
- Application-логика аналитики и истории продаж;
- PostgreSQL схема, миграции и seed;
- React dashboard и Nginx proxy;
- OpenTelemetry и Compose окружение.

## Уровни проверок

| Уровень | Назначение | Инструмент |
| --- | --- | --- |
| Unit | Чистые правила и преобразования | NUnit |
| Integration | Реальные SQL, PostgreSQL, границы и агрегаты | NUnit + Testcontainers |
| Backend E2E | Полный HTTP путь и повторный запуск | NUnit + Kestrel |
| Browser E2E | Пользовательские сценарии UI | NUnit + Playwright |
| Smoke | Сборка и запуск Compose | Docker Compose, HTTP |
| Manual | Визуальная и UX-проверка | Chromium |

## Приоритеты

- P0: KPI, фильтр периода, статусы, доступность приложения, отсутствие
  некорректных финансовых итогов.
- P1: рейтинг, график, категории, товары, история и ошибки.
- P2: адаптивность, telemetry, кэширование, производительность и документация.

## Критерии входа

- доступен Docker daemon;
- зависимости восстановлены;
- миграции находятся в репозитории;
- seed и бизнес-правила согласованы с `docs/business-rules.md`.

## Критерии выхода

- все P0-сценарии пройдены;
- автоматические тесты завершились без ошибок;
- нет открытых дефектов P0/P1 без принятого решения;
- Compose smoke-test успешен;
- результат и ограничения записаны в execution report.

## Не входит в текущий scope

Аутентификация, авторизация, production TLS, внешнее развертывание,
нагрузочный SLA и полноценное управление данными через UI.
