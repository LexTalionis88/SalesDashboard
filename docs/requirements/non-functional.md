# Нефункциональные требования и ограничения

Источник: PDF в корне. MUST/SHOULD/MAY означают обязательное требование, пожелание и допустимую опцию. Здесь отдельно отмечены ограничения технологии, поставки и процесса: они не являются пользовательскими функциями, но влияют на приёмку.

## Явно вне scope

Login, JWT, регистрация, OAuth, пользователи и permissions; mobile layout; отдельная admin panel; Kubernetes; production cloud deployment; сложная distributed architecture и неоправданные микросервисы (§13, с.8; §20, с.11). Пользователь считается уже вошедшим и имеющим доступ.

## Чего ТЗ не нормирует

Не заданы SLA/latency, число параллельных пользователей, предельный диапазон дат, объём данных сверх seed, точные браузеры, валюта/локаль/timezone, требуемые версии библиотек выше минимума .NET 8+, WCAG, покрытие тестами, RPO/RTO. Эти параметры нельзя выдавать за требования заказчика. Предложения по ним при необходимости фиксируются как собственные решения.
