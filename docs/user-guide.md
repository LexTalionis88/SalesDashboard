# Руководство пользователя

## Назначение

Sales Performance Dashboard показывает сводную аналитику продаж за выбранный
период. Приложение предназначено для просмотра показателей команды, динамики,
рейтинга менеджеров, категорий, товаров и последних продаж.

## Запуск

Для локального запуска установите Docker Desktop и выполните в корне проекта:

```sh
docker compose up --build
```

Откройте dashboard в браузере:

<http://localhost:3000>

При первом запуске приложение создаёт структуру базы и демонстрационные данные.
Это может занять немного больше времени, чем последующие запуски.

Остановка приложения:

```sh
docker compose down
```

Команда `docker compose down` останавливает контейнеры, но сохраняет данные в
именованном volume. Для полного сброса демонстрационной базы используйте:

```sh
docker compose down -v
```

## Выбор периода

В верхней части страницы доступны готовые периоды:

- Сегодня;
- 7 дней;
- 30 дней;
- Этот месяц;
- Прошлый месяц;
- Период — ручной выбор дат.

При ручном выборе дата окончания не может быть раньше даты начала. Пока период
некорректен, запросы к API не выполняются и показывается пояснение.

Периоды рассчитываются в часовом поясе `Europe/Moscow`. Границы периода
включительные: выбранные даты входят в отчёт полностью.

## Блок KPI

В верхних карточках отображаются:

- Выручка — сумма цен позиций оплаченных продаж;
- Валовая прибыль — выручка за вычетом себестоимости;
- Продажи — количество оплаченных продаж;
- Средний чек — выручка, делённая на количество оплаченных продаж;
- Маржинальность — валовая прибыль, делённая на выручку.

В KPI учитываются только продажи со статусом `Paid`. Продажи со статусами
`Cancelled` и `Refunded` не входят в финансовые итоги.

Проценты и пункты показывают изменение относительно предыдущего периода такой
же календарной длительности. Если сравнение невозможно, вместо значения
показывается прочерк.

## График

График показывает по дням:

- выручку;
- валовую прибыль;
- количество оплаченных продаж.

Для дней без оплаченных продаж отображаются нулевые значения. Денежные значения
считаются на сервере и форматируются в интерфейсе.

## Рейтинг менеджеров

Рейтинг можно переключать между двумя вариантами:

- валовая прибыль;
- средний чек.

Менеджеры с продажами сортируются по выбранному показателю. Менеджеры без
оплаченных продаж остаются в списке, но не получают места в рейтинге.

Карточка лидера периода всегда определяется по валовой прибыли. Она не зависит
от выбранного способа сортировки рейтинга.

## Категории и товары

Блок категорий показывает вклад каждой категории в выручку выбранного периода.
Ниже отображаются пять товаров с наибольшей валовой прибылью.

Если в периоде нет оплаченных продаж, показывается пустое состояние вместо
нулевого или вводящего в заблуждение рейтинга.

## История продаж

История загружается отдельно от аналитики и содержит последние продажи периода.
Для каждой записи доступны:

- дата;
- клиент и товары;
- менеджер;
- сумма;
- валовая прибыль;
- статус.

В истории могут отображаться отменённые и возвращённые продажи. Они помечены
своими статусами и не включаются в KPI.

## Загрузка и ошибки

При смене периода старый запрос отменяется, чтобы результат устаревшего ответа
не заменил данные нового периода.

Если API временно недоступен, dashboard показывает сообщение об ошибке и кнопку
повторной загрузки. Ошибка истории продаж не скрывает уже загруженную аналитику.

При пустом периоде dashboard показывает понятное сообщение и сохраняет структуру
страницы: график, категории и история не подменяются случайными данными.

## Если приложение не открывается

1. Проверьте, что Docker Desktop запущен.
2. Убедитесь, что порты `3000`, `8080`, `54329`, `16686` и `52323` свободны.
3. Посмотрите состояние контейнеров:

   ```sh
   docker compose ps
   ```

4. Посмотрите логи backend:

   ```sh
   docker compose logs backend
   ```

5. Для повторного создания демонстрационной базы остановите Compose с ключом
   `-v` и запустите его снова.
