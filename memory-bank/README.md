# Memory bank

Назначение: сохранять контекст между сессиями. Подробные требования и проектные решения хранятся в `docs/`; memory bank содержит краткое состояние и ссылки, чтобы не создавать расходящиеся копии.

## Порядок чтения

1. [projectbrief.md](projectbrief.md) — задача, scope и критерий результата.
2. [activeContext.md](activeContext.md) — текущий этап и ближайшая работа.
3. [progress.md](progress.md) — что фактически готово и что нет.
4. [productContext.md](productContext.md) — пользователь и продуктовый смысл.
5. [systemPatterns.md](systemPatterns.md) — архитектурные договорённости и предложения.
6. [techContext.md](techContext.md) — стек, окружение, готовность запуска.

## Правила актуализации

После каждого содержательного этапа обновлять activeContext и progress; при изменении архитектуры — systemPatterns, при изменении инструментов/версий — techContext. Бизнес-правила менять в `docs/business-rules.md`, решения — в `docs/decisions/open-decisions.md`, затем синхронизировать README. Статусы: готово / запланировано / требует решения / ограничение. Не смешивать проект с реализованным поведением.

Пользовательские запросы сохраняются в корневом `AI_PROMPTS.md`, рефлексия — в `AI_NOTES.md`. Секреты и служебные инструкции в memory bank не сохранять.
